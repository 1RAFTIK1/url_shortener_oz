# URL Shortener

Сервис сокращения ссылок на Go: HTTP API, два взаимозаменяемых хранилища
(PostgreSQL и собственное в памяти), Docker-образ на 13.4 МБ, тесты.

Тестовое задание на стажировку Go-разработчика в Ozon Банк.

## Быстрый старт

```bash
docker compose up -d
```

```bash
curl -XPOST localhost:8081/api/v1/links \
  -H 'Content-Type: application/json' \
  -d '{"url":"https://ozon.ru/category/smartfony"}'
```

```json
{
  "code": "JL874tdenr",
  "short_url": "http://localhost:8081/JL874tdenr",
  "url": "https://ozon.ru/category/smartfony",
  "created_at": "2026-08-04T17:09:17.451432Z"
}
```

```bash
curl localhost:8081/JL874tdenr
```

Без Docker, с хранилищем в памяти:

```bash
go run ./cmd/shortener -storage=memory
```

## API

| Метод | Путь | Ответ |
|---|---|---|
| `POST` | `/api/v1/links` | `201` — ссылка создана, `200` — уже существовала |
| `GET` | `/{code}` | `200` с оригинальным адресом |
| `GET` | `/healthz` | процесс жив |
| `GET` | `/readyz` | хранилище доступно |

Повторный `POST` того же адреса возвращает **ту же** ссылку и `200` вместо
`201`, поэтому запрос безопасно повторять после таймаута.

Ошибки — единым конвертом:

```json
{"error": {"code": "invalid_url", "message": "url должен быть абсолютным http(s)-адресом без учётных данных"}}
```

| Код | HTTP | Когда |
|---|---|---|
| `bad_request` | 400 | тело не JSON, пустое или содержит лишние поля |
| `invalid_url` | 400 | не абсолютный http(s)-адрес либо адрес с учётными данными |
| `url_too_long` | 400 | длиннее 2048 символов |
| `invalid_code` | 400 | код не из 10 символов алфавита |
| `not_found` | 404 | такой ссылки нет |
| `method_not_allowed` | 405 | метод не поддерживается (в `Allow` — какой нужен) |
| `unsupported_media_type` | 415 | не `application/json` |
| `payload_too_large` | 413 | тело больше 8 КиБ |
| `storage_full` | 503 | хранилище в памяти достигло предела |
| `storage_unavailable` | 503 | база недоступна, повтор имеет смысл |
| `timeout` | 504 | не уложились в `-request-timeout` |
| `internal_error` | 500 | всё остальное |

Каждый ответ несёт `X-Request-Id`; если клиент прислал свой — он сохраняется.

## Конфигурация

Приоритет: флаг → переменная окружения → значение по умолчанию.
Некорректная конфигурация не даёт сервису стартовать.

| Флаг | Переменная | По умолчанию | Назначение |
|---|---|---|---|
| `-storage` | `STORAGE` | `memory` | `memory` или `postgres` |
| `-http-addr` | `HTTP_ADDR` | `:8081` | адрес HTTP-сервера |
| `-base-url` | `BASE_URL` | из `-http-addr` | префикс коротких ссылок |
| `-postgres-dsn` | `POSTGRES_DSN` | — | обязателен при `-storage=postgres` |
| `-memory-max-entries` | `MEMORY_MAX_ENTRIES` | `1000000` | предел ссылок в памяти, `0` — без предела |
| `-memory-ttl` | `MEMORY_TTL` | `0` | срок жизни ссылки в памяти |
| `-request-timeout` | `REQUEST_TIMEOUT` | `5s` | предельное время обработки запроса |
| `-shutdown-timeout` | `SHUTDOWN_TIMEOUT` | `10s` | ожидание активных запросов при остановке |
| `-log-level` | `LOG_LEVEL` | `info` | `debug`, `info`, `warn`, `error` |

## Как генерируются коды

Код — 10 символов из алфавита `[a-zA-Z0-9_]`, то есть 63 символа;
пространство `63^10 ≈ 9.85·10^17`.

Байты берутся из `crypto/rand`. Так как 63 не степень двойки, наивное `b % 63`
дало бы смещение — остатки 0–3 выпадали бы чаще. Поэтому байты `≥ 252`
(наибольшее кратное 63 в пределах байта) **отбрасываются**; доля отказов 1.56%.

Уникальность обеспечивает не вероятность, а уникальный индекс хранилища: при
коллизии `Save` возвращает `ErrCodeTaken`, и сервис берёт новый код (до трёх
попыток). Вероятность определяет лишь частоту повторов: при миллиарде
сохранённых ссылок это один повтор на миллиард вставок.

Генерация занимает ~114 нс (`go test ./internal/codegen -bench=Generate`).

## Принятые решения

- **`GET` возвращает JSON, а не редирект.** В ТЗ дословно: «Метод Get, который
  будет принимать сокращённый URL и *возвращать оригинальный URL*». Требуется
  вернуть адрес, а не перенаправить на него. Если бы редирект понадобился, это
  `302 Found`, а не `301`: постоянный редирект браузеры кэшируют бессрочно,
  после чего ни собрать статистику, ни отозвать ссылку невозможно.
- **Дедупликация по нормализованному адресу.** Схема и хост приводятся к
  нижнему регистру, порт по умолчанию отбрасывается, пустой путь становится
  `/`. Завершающий слэш у непустого пути сохраняется: `/a` и `/a/` могут быть
  разными ресурсами.
- **Адреса с учётными данными отвергаются** — короткая ссылка, скрывающая
  `http://user:pass@bank.example.com`, это фишинг.
- **Роутер из стандартной библиотеки.** С Go 1.22 `ServeMux` понимает метод в
  шаблоне и параметры пути, поэтому внешний роутер не нужен.
- **Прямые зависимости — четыре**: `pgx/v5` (драйвер), `goose` (миграции) и две
  `testcontainers` только для тестов. Ни роутера, ни валидатора, ни
  конфиг-библиотеки, ни testify.

## Поведение под нагрузкой и при долгой работе

- Проверка и вставка атомарны: `INSERT ... ON CONFLICT DO NOTHING` в Postgres,
  одна критическая секция в памяти. Сто одновременных запросов одного адреса
  дают одну ссылку — это покрыто тестом в обоих хранилищах.
- Хранилище в памяти ограничено по ёмкости и умеет TTL с фоновой очисткой,
  поэтому месяцы работы не заканчиваются OOM.
- Пул Postgres ограничивает время жизни и простоя соединений, чтобы за месяцы
  не накопились мёртвые соединения за NAT.
- `ReadHeaderTimeout` против Slowloris, лимит тела 8 КиБ, таймаут на запрос,
  корректная остановка по `SIGTERM`.
- Миграции применяются под сессионной блокировкой, поэтому одновременный старт
  нескольких инстансов безопасен.

## Разработка

```bash
make test    # быстрый прогон
make race    # с детектором гонок
make cover   # покрытие
make lint    # golangci-lint
make check   # race + lint + govulncheck
```

```bash
go test -tags=integration ./...   # интеграционные тесты, нужен Docker
```

Файлы под тегом `integration` невидимы для gopls по умолчанию — в
`.vscode/settings.json` для этого прописан `buildFlags`.
